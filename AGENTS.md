# AGENTS.md

## 1. Descripción del proyecto

Este repositorio contiene la versión 2 del portfolio profesional de Marcos Andrés Travaglini.

La versión anterior fue desarrollada con React, Vite, TypeScript y Tailwind CSS. La nueva versión se reconstruye desde cero utilizando Astro, TypeScript y CSS.

El objetivo principal del proyecto es mejorar la empleabilidad de Marcos como Frontend Developer, presentando de forma clara:

- Su experiencia práctica en equipos.
- Sus proyectos reales y colaborativos.
- Sus aportes técnicos concretos.
- Su capacidad para trabajar con React, TypeScript, UI responsive y APIs.
- Su formación universitaria.
- Su disposición para aprender mediante code review y acompañamiento técnico.

Este proyecto no debe convertirse en:

- Un template genérico de portfolio.
- Una demostración innecesaria de tecnologías.
- Una landing de startup.
- Una página sobrecargada de animaciones.
- Una presentación que exagere el nivel profesional de Marcos.

## 6. Stack técnico del proyecto

- CSS
- Bun

- prettier-plugin-astro

No instalar React, Vue, Svelte, Solid u otro framework sin una necesidad concreta y aprobación previa.

No instalar dependencias nuevas sin:

1. Explicar qué problema resuelven.
2. Confirmar que Astro o CSS nativo no cubren la necesidad.
3. Evaluar impacto en bundle, mantenimiento y complejidad.
4. Obtener aprobación antes de instalarlas.

## 7. Gestor de paquetes

Usar exclusivamente Bun.

Comandos válidos:

```bash
bun install
bun add <package>
bun add --dev <package>
bun run dev
bun run check
bun run format
bun run format:fix
bun run build
bun run preview
bun run quality
```

No utilizar:

- npm
- pnpm
- Yarn

No eliminar ni regenerar `bun.lock` sin una razón técnica comprobable.

## 8. Flujo obligatorio antes de modificar código

Antes de realizar cambios:

1. Leer este archivo completo.
2. Leer `README.md`.
3. Leer `package.json`.
4. Leer `astro.config.mjs`.
5. Leer `tsconfig.json`.
6. Leer `.prettierrc`.
7. Revisar los archivos relevantes dentro de `src/`.
8. Revisar el estado actual antes de proponer una solución.
9. Explicar brevemente el plan.
10. Mantener el cambio limitado al alcance solicitado.

No comenzar modificando archivos sin auditar primero la implementación existente.

## 9. Validaciones obligatorias

Después de modificar código ejecutar:

```bash
bun run check
bun run format:fix
bun run format
bun run build
```

Cuando exista el script general:

```bash

```

```bash

bun run format
bun run build
```

No considerar una tarea terminada mientras alguna validación falle.

En la entrega final informar el resultado exacto:

- Cantidad de errores.
- Cantidad de warnings.
- Resultado de Prettier.
